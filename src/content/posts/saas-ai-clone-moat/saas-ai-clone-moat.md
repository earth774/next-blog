ขอเริ่มจากเรื่องที่ทำให้ผมนั่งคิดอยู่หลายวันครับ

ช่วงที่ผ่านมา ผมเห็น analytics tool สไตล์ DataFast โผล่มาในไทม์ไลน์แทบทุกอาทิตย์

หน้าตาคล้ายกัน dashboard คล้ายกัน ขายจุดเดียวกันว่า "รู้ว่ารายได้มาจาก traffic ช่องไหน" ต่างกันแค่ราคา

ตัวหนึ่งถูกกว่าครึ่ง อีกตัว self-host ฟรี อีกตัวบอกว่า "ทำเสร็จในสุดสัปดาห์เดียวด้วย AI"

ผมไม่ได้รู้สึกตลกนะครับ ผมรู้สึกเสียวสันหลัง

เพราะถ้าของที่คนอื่นใช้เวลาเป็นเดือนสร้าง ถูกทำซ้ำได้ในสองวัน ของที่ผมกำลังทำอยู่ก็โดนแบบเดียวกันได้เหมือนกัน

## เมื่อ clone ถูกกว่าการคิด

ก่อนยุค AI coding agent การ clone SaaS สักตัวมีต้นทุนจริง

ต้องมีคนเขียน backend ทำ auth ต่อ payment ดูแล infra กว่าจะได้ของที่ใช้ได้ก็หลายเดือน ต้นทุนตรงนี้เองที่เป็นกำแพงกันคู่แข่งแบบไม่ตั้งใจ

ทุกวันนี้กำแพงนั้นบางลงมาก

เปิดหน้า landing page ของคนอื่น ถ่าย screenshot ให้ agent ดู อธิบาย flow หลัก แล้วปล่อยมันทำงาน ภายในไม่กี่วันก็ได้ของที่ "หน้าตาเหมือน" และ "ทำงานได้ประมาณนั้น"

เมื่อทุกคนสร้างของเหมือนกันได้ สิ่งเดียวที่เหลือให้แข่งก็คือราคา

แล้วราคาก็ไหลลงเรื่อย ๆ จากรายเดือนเป็นจ่ายครั้งเดียว จากจ่ายครั้งเดียวเป็นฟรี จากฟรีเป็น open source ให้ไป self-host เอง

นี่คือสิ่งที่ผมเรียกว่าราคาพัง ไม่ได้พังเพราะของไม่ดี แต่พังเพราะของไม่ต่างกัน

## Feature parity ไม่ใช่ข้อได้เปรียบอีกต่อไป

สมัยก่อนเวลาวางแผน product ผมชอบทำตารางเทียบ feature กับคู่แข่ง

ช่องไหนเรามีแต่เขาไม่มี ก็ติ๊กเขียวไว้ แล้วรู้สึกว่าเราชนะ

ตอนนี้ตารางแบบนั้นแทบไม่มีความหมาย

feature ที่เราใช้สองอาทิตย์ทำ คู่แข่งที่มี agent ดี ๆ ใช้บ่ายเดียวก็ตามทัน บางทีทำได้ดีกว่าด้วยซ้ำ เพราะเขาเห็นของเราเป็นตัวอย่างแล้ว

ในมุม PM สิ่งที่ผมได้เรียนรู้คือ **อะไรที่อยู่ในโค้ดล้วน ๆ ให้ถือว่าถูกก๊อปได้เสมอ**

ถ้า moat ของเราคือ "เรามี feature นี้" แปลว่าเราไม่มี moat

## แล้วอะไรยังเป็น moat

ผมลองไล่ดู SaaS ที่ยังขายได้ดีทั้งที่มีตัว clone ราคาถูกเต็มตลาด แล้วสังเกตว่าสิ่งที่ทำให้คนยังจ่ายมักไม่ได้อยู่ในโค้ดเลย

**1. Distribution**

คนที่มีคนฟังอยู่แล้ว ปล่อยของวันแรกก็มีลูกค้า คนที่ไม่มีต่อให้ของดีกว่าก็เงียบ

clone ก๊อป feature ได้ แต่ก๊อปคนดู ก๊อปความสัมพันธ์กับ community ที่สะสมมาเป็นปีไม่ได้

**2. Brand trust**

โดยเฉพาะของที่แตะข้อมูลสำคัญ อย่าง analytics การเงิน หรือข้อมูลลูกค้า คนไม่ได้ซื้อแค่ dashboard เขาซื้อความมั่นใจว่าของจะไม่หาย ไม่รั่ว และเจ้าของจะยังอยู่ปีหน้า

ตัวที่ถูกกว่าครึ่งแต่เพิ่งเกิดเมื่อวาน ตอบคำถามนี้ไม่ได้

**3. Data และ network effects**

ถ้า product ยิ่งมีคนใช้ยิ่งฉลาดขึ้น ยิ่งมี template ยิ่งมี integration ยิ่งมีข้อมูลเปรียบเทียบที่มีค่า ตัว clone ที่เริ่มจากศูนย์ก็ต้องเริ่มจากศูนย์จริง ๆ

โค้ดก๊อปได้ แต่ข้อมูลที่สะสมจากผู้ใช้หลายพันคนก๊อปไม่ได้

**4. ความสัมพันธ์ใน niche**

ถ้าเรารู้จักลูกค้ากลุ่มหนึ่งลึกพอ รู้ว่าเขาใช้ศัพท์อะไร เจ็บตรงไหน ทำงานกับเครื่องมืออะไร เราจะออกแบบได้ตรงกว่าคนที่แค่ก๊อปหน้าจอ

ลูกค้า niche มักจะภักดี เพราะเขาเบื่อของที่ทำมาเพื่อ "ทุกคน"

**5. Support และ ops**

ตอนระบบล่มตีสอง ใครตอบ ตอนลูกค้า import ข้อมูลพัง ใครช่วย

เรื่องพวกนี้ไม่ได้อยู่บน landing page แต่เป็นเหตุผลที่คนไม่ยอมย้ายออก

**6. Switching cost ที่ไม่ใช่โค้ด**

workflow ที่ทีมลูกค้าผูกไว้ ข้อมูลย้อนหลังหลายปี คนในทีมที่ใช้คล่องแล้ว report ที่ส่งหัวหน้าทุกจันทร์

ของพวกนี้ทำให้การย้ายไปตัวที่ถูกกว่า "ไม่คุ้มเหนื่อย" ถึงจะประหยัดเงินได้บ้างก็ตาม

แต่ต้องระวังนิดหนึ่งครับ switching cost ที่ดีคือ "อยู่แล้วสบาย" ไม่ใช่ "ขังไว้ไม่ให้ออก" ถ้าลูกค้ารู้สึกว่าถูกล็อก เขาจะหาทางออกทันทีที่มีโอกาส

## ความจริงของ indie dev

ผมเองก็เคยเป็นสายนี้ครับ เห็น SaaS ขายดีตัวหนึ่ง แล้วคิดว่า "อันนี้เราทำได้ ทำให้ถูกกว่า ทำให้สวยกว่า"

ทำได้จริงครับ แต่สิ่งที่ไม่เคยคิดคือ ถ้าเราทำได้ คนอื่นอีกร้อยคนก็ทำได้

และในร้อยคนนั้น มีคนที่ยอมขายถูกกว่าเรา มีคนที่ยอมแจกฟรีเพื่อเอาชื่อ และมีคนที่มี audience ใหญ่กว่าเราสิบเท่า

แข่งด้วย feature อย่างเดียว ในยุคที่ feature ถูกที่สุด คือการเลือกสนามที่เราแพ้แน่

สิ่งที่ผมเปลี่ยนคือ ก่อนเริ่ม project ใหม่ ผมถามตัวเองเพิ่มอีกหนึ่งคำถาม

> "ถ้ามีคน clone ของนี้ได้ในสามวัน ทำไมลูกค้ายังจะเลือกเรา"

ถ้าตอบไม่ได้ ผมยังไม่เริ่มเขียนโค้ด

## ออกแบบ moat ตั้งแต่วันแรก ทำยังไง

นี่คือสิ่งที่ผมลองใช้จริงกับ side project ช่วงหลัง ไม่ได้สมบูรณ์ แต่ช่วยได้เยอะ

**เลือก niche ที่เราคุยกับเขาได้จริง**

ไม่ใช่ "SME ทั่วไป" แต่เป็น "ร้านกาแฟที่มีสองสาขาขึ้นไป" หรือ "ทีม dev ไทยที่ใช้ Laravel" กลุ่มที่เรารู้ว่าเขาอยู่ที่ไหน และทักไปถามได้พรุ่งนี้

ถ้านึกชื่อคนในกลุ่มนั้นไม่ออกสักห้าคน niche นั้นยังกว้างเกินไป

**มีช่องทางเป็นของตัวเอง**

blog, newsletter, กลุ่ม community, ช่อง YouTube อะไรก็ได้ที่เราไม่ต้องจ่ายค่าโฆษณาทุกครั้งที่อยากให้คนเห็น

ช่องทางนี้ใช้เวลาสร้างนาน และนั่นแหละคือเหตุผลที่มันเป็น moat

**Ship trust กับ ops ไม่ใช่แค่ UI**

เขียน changelog สม่ำเสมอ มีหน้า status ตอบ support เร็ว บอกตรง ๆ ว่าเก็บข้อมูลอะไร ลบยังไง มี export ให้

ของพวกนี้ดูน่าเบื่อ แต่ตัว clone ส่วนใหญ่ข้าม เพราะมันไม่สนุกเท่าทำ feature

**สะสมสิ่งที่โตตามเวลา**

ข้อมูลที่มีค่า template ที่ผู้ใช้แชร์กัน integration กับเครื่องมือเฉพาะใน niche ชื่อเสียงจากเคสลูกค้าจริง

ถามตัวเองทุกเดือนว่า "เดือนนี้เราสะสมอะไรที่คนเริ่มใหม่ตามไม่ทัน"

**ใช้ AI ให้เป็นประโยชน์กับเราเหมือนกัน**

ถ้าคนอื่น clone เราได้เร็ว เราก็ใช้ AI ปิดงานจุกจิกให้เร็วเหมือนกัน แล้วเอาเวลาที่เหลือไปคุยกับลูกค้า ทำ content และดูแลคน ซึ่งเป็นงานที่ agent ทำแทนเราไม่ได้

## ท้ายที่สุด

ตอนเห็นตัว clone โผล่มาเต็มไทม์ไลน์ครั้งแรก ผมรู้สึกว่าโลกมันใจร้ายกับคนทำ SaaS เล็ก ๆ

แต่พอคิดอีกที มันแค่บังคับให้เราตอบคำถามที่ควรตอบตั้งแต่แรก

ลูกค้าไม่ได้จ่ายเงินให้โค้ดของเรา เขาจ่ายให้ปัญหาที่หายไป ความมั่นใจว่าจะไม่พัง และคนที่จะอยู่ตรงนั้นตอนเขาต้องการ

โค้ดถูกลงทุกวัน แต่ความไว้ใจยังแพงเท่าเดิม

ผมยังเขียนโค้ดสนุกเหมือนเดิมครับ แค่ตอนนี้ก่อนกด `npm create` ผมจะถามตัวเองก่อนว่า moat ของ project นี้อยู่ตรงไหน
