ขอพูดประเด็นก่อนเลยครับ

เขียนโค้ดเก่งอย่างเดียวไม่พอแล้ว

ไม่ใช่เพราะทักษะเราด้อยค่าลง แต่เพราะ AI ทำให้การ "สร้างของ" ถูกและเร็วลงมากจนของที่ใช้งานได้ไม่ใช่ของหายากอีกต่อไป

สิ่งที่ยังหายากคือคนเห็น คนเชื่อ และคนยอมจ่าย

## ของที่ผมสร้างเสร็จ แต่ไม่มีใครเคยเห็น

ผมเป็นเดฟที่ต้องทำงาน PM ด้วย เวลาว่างจริง ๆ เหลือไม่เยอะ

แต่ปีที่ผ่านมาผมปล่อย side project ออกไปหลายตัว ตัวที่เร็วสุดใช้เวลาเสาร์เดียว เพราะมี AI agent ช่วยร่างโครง ช่วย debug ช่วยเขียน test

ตอนกด deploy ผมรู้สึกดีมาก ของทำงานได้ หน้าตาไม่น่าเกลียด โค้ดก็พอรับได้

แล้วอีกสองอาทิตย์ผมเปิด analytics ดู

ผู้ใช้สิบกว่าคน ครึ่งหนึ่งคือตัวผมเอง

ตอนแรกผมคิดว่าของยังไม่ดีพอ ก็เลยกลับไปแก้ เพิ่ม feature ขัด UI ปรับ performance

แก้ไปสามรอบ ตัวเลขก็ยังเท่าเดิม

สุดท้ายผมถึงยอมรับว่าปัญหาไม่ได้อยู่ในโค้ด มันอยู่ตรงที่ไม่มีใครรู้ว่าของนี้มีอยู่ และไม่มีใครรู้ว่ามันแก้ปัญหาอะไรให้เขา

นั่นไม่ใช่ปัญหาวิศวกรรม นั่นคือ marketing

## อะไรเปลี่ยนไปจริง ๆ

ก่อนหน้านี้ การเขียนโค้ดเป็นคอขวด

ใครทำ CRUD ได้ครบ จัดการ auth ได้ ขึ้น server ได้ คนนั้นมีของที่คนอื่นทำไม่ได้ ความหายากอยู่ที่ฝีมือ

ทุกวันนี้คอขวดนั้นกว้างขึ้นมาก คนที่พอเขียนโค้ดเป็นบวกกับ AI agent ดี ๆ สามารถปล่อยของที่ใช้งานได้ภายในสุดสัปดาห์เดียว

เมื่อการสร้างถูกลง จำนวนของก็เยอะขึ้นมหาศาล และความสนใจของคนก็ยังเท่าเดิม

ของที่หายากเลยย้ายที่

- **Distribution** เรามีช่องทางที่พูดแล้วมีคนฟังไหม
- **Trust** ทำไมเขาต้องเชื่อว่าของเราใช้ได้จริง
- **Niche** เราชัดไหมว่าของนี้ทำให้ "ใคร" ไม่ใช่ "ทุกคน"

สามข้อนี้ AI ช่วยเร่งได้บ้าง แต่สร้างให้เราทั้งหมดไม่ได้ เพราะมันต้องสะสมด้วยเวลาและชื่อของเราเอง

## marketing literacy ไม่ใช่การเป็น marketer

ผมไม่ได้ชวนให้เลิกเขียนโค้ดไปทำ growth hacking นะครับ

สิ่งที่ผมหมายถึงคือระดับ "อ่านออกเขียนได้" แค่พอให้ของที่เราทำมีโอกาสถึงมือคน

เทียบง่าย ๆ เราไม่ต้องเป็น DBA แต่เราควรรู้ว่า index คืออะไร เพื่อไม่เขียน query ที่ฆ่า production

marketing ก็เหมือนกัน ไม่ต้องเก่งซื้อ ads ไม่ต้องทำ funnel ซับซ้อน แต่ควรตอบสี่คำถามนี้ได้

1. ของนี้ทำให้ใคร
2. มันแก้ปัญหาอะไรที่เขารู้สึกเจ็บจริง
3. เขาจะเจอของนี้ได้จากที่ไหน
4. ทำไมเขาต้องเชื่อเรา

ผมเคยคิดว่าคำถามพวกนี้ fluffy ไม่มีสาระ จนมานั่งตอบจริง ๆ แล้วพบว่าตอบไม่ได้สักข้อ

ตอนนั้นผมมีแค่ feature list ไม่ได้มีเหตุผลให้ใครใช้

## สี่อย่างที่ทำได้จริงแม้เวลาไม่เหลือ

นี่คือของที่ผมลองแล้วและพอทำได้โดยไม่กระทบงานประจำ

### เลือกช่องทางเดียว แล้วอยู่ให้นาน

ตอนแรกผมเปิดทุกที่ X, LinkedIn, Threads, YouTube, บล็อก

ผลคือโพสต์กระจัดกระจาย ไม่มีที่ไหนที่คนจำเราได้

เลิกทำแบบนั้นแล้วครับ เลือกที่เดียวที่กลุ่มคนที่เราอยากคุยด้วยอยู่จริง แล้วอยู่ที่นั่นให้สม่ำเสมอเป็นปี

ของผมคือบล็อกเป็นบ้าน แล้วใช้ช่องทางอื่นเป็นทางเดินเข้าบ้าน

### เขียนในที่สาธารณะระหว่างทาง

ไม่ต้องรอให้ของเสร็จก่อนถึงจะพูดถึง

ผมเขียนตอนยังทำไม่เสร็จด้วย ปัญหาที่เจอ ทางที่เลือก ของที่พัง

สองอย่างเกิดขึ้นพร้อมกัน คนเริ่มรู้ว่าเราทำเรื่องนี้ และตัวเราคิดชัดขึ้นเพราะต้องอธิบายให้คนอื่นเข้าใจ

สำหรับเดฟ นี่คือ marketing ที่ต้นทุนต่ำที่สุด เพราะเราเล่าสิ่งที่เราทำอยู่แล้ว

### คุยกับคนใช้ อย่างน้อยเดือนละคน

ข้อนี้ผมอึดอัดที่สุด เพราะถนัดอยู่กับ terminal มากกว่าอยู่กับคน

แต่บทสนทนายี่สิบนาทีเดียวประหยัดเวลาผมได้เป็นเดือน

หลายครั้ง feature ที่ผมตั้งใจทำต่ออีกสองสัปดาห์ กลายเป็นเรื่องที่เขาไม่สนใจเลย ส่วนเรื่องที่เขาเจ็บจริงคือสิ่งที่ผมมองข้ามไปตั้งแต่ต้น

ไม่ต้องทำ user research เป็นระบบ แค่ถามว่า "ตอนนี้ทำเรื่องนี้ยังไงอยู่" แล้วฟังให้จบ

### แพ็กของให้คนเข้าใจในประโยคเดียว

ของดีที่อธิบายไม่ได้ ก็เหมือนไม่มี

ผมเคยเขียนหน้าแรกว่า "เครื่องมือจัดการงานที่ยืดหยุ่น รองรับหลายรูปแบบการทำงาน"

อ่านแล้วไม่มีใครรู้ว่ามันทำอะไร

เปลี่ยนเป็นประโยคที่ชี้ชัดว่าใครและได้อะไร เช่น "ช่วยฟรีแลนซ์ออกใบเสนอราคาและใบแจ้งหนี้ให้ลูกค้าไทยภายในสามนาที"

ยอดใช้งานไม่ได้ระเบิด แต่คนที่เข้ามาแล้วอยู่ต่อเพิ่มขึ้นชัดเจน เพราะมาถูกที่ตั้งแต่แรก

## ทักษะเดฟยังสำคัญอยู่ และสำคัญมาก

เรื่องนี้ต้องพูดให้ชัด

ผมไม่ได้บอกว่าฝีมือเขียนโค้ดไม่สำคัญแล้ว

ของที่พังตอนมีผู้ใช้จริงยังเป็นเรื่องใหญ่ ความเข้าใจระบบ ความปลอดภัย ความเป็นเจ้าของโค้ด ยังคือสิ่งที่แยกของที่อยู่ได้นานกับ demo ที่สวยอาทิตย์เดียว

แต่ทักษะเดฟที่ไม่มี distribution จะได้ผลตอบแทนน้อยกว่าที่ควรเสมอ

ส่วน distribution ที่ไม่มีของดีรองรับ ก็อยู่ได้แค่รอบเดียว

สองอย่างนี้คูณกัน ไม่ใช่เลือกอย่างใดอย่างหนึ่ง

## ท้ายที่สุด

สิ่งที่ผมเสียดายที่สุดไม่ใช่ project ที่ล้ม

แต่เป็น project ที่ทำเสร็จดีแล้ว และไม่เคยมีใครได้ลองใช้เลย เพราะผมไม่กล้าเล่าให้ใครฟัง

AI ทำให้การ ship ง่ายขึ้นจริง แต่มันก็ทำให้ของที่ ship ออกมาแข่งกันหนักขึ้นด้วย

ถ้าปีนี้จะเพิ่มทักษะใหม่หนึ่งอย่าง ผมแนะนำว่าอย่าเป็นภาษาที่สี่หรือ framework ตัวใหม่

ลองเป็นความสามารถในการอธิบายของที่เราทำ ให้คนที่ไม่ใช่เดฟฟังแล้วอยากลอง

ของผมยังทำอยู่ครับ ยังเขินตอนกดโพสต์ทุกครั้ง แค่ตอนนี้กดส่งเร็วขึ้นกว่าเดิมหน่อย
